Project overview

What this assignment does

It turns a seasonal radar image stack into a binary land-cover classification and summarizes mapped class area.

01 / OBJECTIVE

Build seasonal radar predictors

Create VV and VH composites from Sentinel-1 observations for three periods across the 2025–26 season.

02 / CLASSIFICATION

Separate crop proxy from other land

Train a Random Forest model using cropland/non-cropland proxy labels derived from ESA WorldCover.

03 / OUTPUT

Assess and summarize

Generate a classified raster, confusion-matrix metrics, class-area statistics, and export tasks from Earth Engine.

Methodology

Workflow at a glance

Follow the steps in order. Run the script in the Code Editor and check the Console, Map and Tasks tabs.

Define study area

Load the Assam state boundary asset and use its geometry as the analysis region.

Prepare Sentinel-1

Filter the IW collection, select VV/VH and build three seasonal composites.

Prepare proxy labels

Use ESA WorldCover class 40 as a cropland proxy and create stratified samples.

Train the model

Split samples 70/30, train a Random Forest classifier and classify the predictor stack.

Evaluate

Review the confusion matrix, overall accuracy and Kappa generated by the held-out split.

Calculate area

Summarize classified pixel counts/area at the scale configured in the script.

Export results

Open Tasks and start the CSV and GeoTIFF exports; wait for each task to complete.

Important interpretation

Validation and limitations

Do not present proxy-based accuracy as independent ground-truth accuracy. ESA WorldCover v200 represents a 2021 land-cover map, so it is not verified field/reference data for the Rabi 2025–26 season. The current workflow is best described as a cropland/non-cropland proxy classification, not identification of individual crop types.

Recommended validation

Use season-matched reference labels, field observations, or an independently interpreted sample. Keep validation samples separate from training and report class-wise precision/recall where possible.

Scale and processing

Coarse-scale settings may be useful to test a state-wide workflow and avoid timeouts. Report the actual analysis scale used, and do not imply finer spatial detail than the exported raster supports.
